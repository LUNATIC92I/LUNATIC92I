# Detection rules

YAML detection rules, organized by category, loaded by the Detection Engine
(`backend/app/detection/`) starting in Phase 6. See
`docs/DEVELOPMENT_PLAN.md` (Phase 6) for the rule schema and the required
positive/negative/boundary test set per rule, and `ARCHITECTURE.md` §7.2 for
the streaming-vs-windowed rule contract.

Subdirectories mirror the rule families from the spec:

- `authentication/` — brute force, password spraying, impossible travel, ...
- `windows/` — suspicious PowerShell, credential dumping indicators, ...
- `linux/` — SSH brute force, privilege escalation indicators, ...
- `network/` — port scanning, C2 indicators, DNS tunneling, ...
- `cloud/` — suspicious API calls, IAM changes, disabled logging, ...
- `email/` — suspicious forwarding rules, mailbox takeover indicators, ...
- `data_security/` — abnormal downloads, possible exfiltration, ...

No rules are shipped yet — this structure exists ahead of Phase 6 content.
